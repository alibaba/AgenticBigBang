# 共享背景 — 中文学术论文幻灯片生成任务合成

你在一个多阶段自动化管线中运行，该管线从单篇中文学术论文 PDF 合成
**PPTSynth 风格的幻灯片生成任务**（一篇论文 → 一个任务案例）。
每个阶段在独立会话、全新上下文窗口中运行。你不会看到之前的对话。
唯一权威的输入是当前工作目录中的文件和本轮给你的 schema。

## PPTSynth 是什么（金标准）

PPTSynth 是一个细粒度、基于评分标准的幻灯片生成基准测试。
本管线按照 PPTSynth 的架构和质量标准，为中文学术会议论文合成
任务案例。这些论文来自多个中文学术会议（中国林业学术大会、
交通能源与智能动力大会、内燃机学术年会、中国农学会全国代表大会、
设计与智能制造学术年会、全国炼钢学术会议等），覆盖林业、
内燃机/燃烧、能源、生态、农业、冶金等 15+ 个学科领域。

每个任务案例包含：

- **`material.pdf`** — 源论文（直接复制）。
- **`generation_task/instructions.md`** — 结构严谨的中文幻灯片生成
  指令，遵循固定的六段式布局（详见下文）。
- **`generation_task/judge_prompt.json`** — 仅含两个实例特定的
  检查列表数组：
  - `material_dependent_checklist_1` — **内容完整性**（11-13 项）
  - `material_dependent_checklist_2` — **内容正确性**（10-12 项）

演示基础检查列表、视觉设计与布局检查列表以及逐页内容保真度检查列表
由共享评估框架配置后期追加，我们在案例文件中不生成它们。

## `instructions.md` 的六段式模板

每个任务以同一句中文开头：

> 请根据论文严格生成一套完整的、达到学术会议质量标准的幻灯片，
> 适用于在学术会议（如中国林业学术大会、交通能源与智能动力大会、
> 内燃机学术年会等）上进行口头报告。幻灯片必须准确、结构清晰，
> 并**忠实于原始论文**，不得包含任何捏造内容。

接着是 **`# **幻灯片的严格约束**`** 和六个编号的章节：

1. **内容要求** — *论文特定*。幻灯片页数范围（根据论文长度确定）。
   按顺序列出的必需幻灯片章节（标题页 / 大纲 / 背景 / 现有方法
   不足 / 方法概述 / 方法论 / 关键实验程序 / 试验材料与数据 /
   实验设置 / 结果 / 视觉分析 / 总结与局限 / 结论）。每个章节
   附带要点列表和可选的 `设计约束:` 行。
2. **内容约束** — 模板文本（忠实性、准确性、简洁性、逻辑、引用）。
3. **视觉与设计** — 模板文本。
4. **文本质量** — 模板文本。
5. **技术忠实性要求** — 半论文特定（定量覆盖、图表可追溯性）。
6. **演示风格与听众** — 模板文本。

最后是 **`# **预期输出**`** 和结束句
`一套满足上述所有约束的**完整幻灯片**。`

## 检查列表风格

`material_dependent_checklist_1` 和 `material_dependent_checklist_2`
均为 JSON 字符串数组。每个字符串是一个完整的 prompt，提交给 MLLM
评判模型，产出二元 `是` 或 `否` 判定。

完整性项（`_1`）询问某内容是否**被包含**：

```
**幻灯片是否清楚定义了"预燃室湍流射流点火"的核心概念，包括其工作
原理和关键特征？**

  注意：您只需检查幻灯片是否包含所需内容，无需验证其正确性。
  如果**否**，描述缺失或不充分之处。
```

正确性项（`_2`）询问某内容是否**准确**，附带具体锚点：

```
**"实验结果"部分的性能数据是否与论文中的表格一致？（例如，压缩比
15:1 时指示热效率约为 46.2%。）**

  如果**否**，列出幻灯片与论文之间的具体差异。
```

每个检查项：

- 以 **加粗问句** 开头，以问号结尾。
- 包含具体锚点——定义的术语、带单位的数值、方法论区分、或评估指标。
- 二元判定；部分满足算 `否`。
- 以简短的"如果**否**，……"指令结尾。

## 适用于所有阶段的硬性规则

1. **输出语言为中文。** 为案例写的每个产物（`instructions.md`、
   `judge_prompt.json`、`_paper_card.json`）都使用中文。论文中的
   英文术语和公式符号保持原文。JSON 键名和 `kind` 枚举值保持英文。
2. **指令读起来像真正的会议报告委托。** 不得包含合成管线自身的
   元语言——不提 `PPTSynth`，不提"自查"页，不说"为满足评分
   要求"。"基准"、"评分标准"、"检查列表"等词仅在论文本身使用
   这些概念时才可出现；判断标准是该句子是在描述论文内容还是自指
   合成任务。
3. **要点是范围，结构字段是答案。** Paper Card 的字段分为两个角色：
   - **范围字段** — `ordered_sections[*].bullets` 和
     `ordered_sections[*].design_constraint`。这些流入
     `instructions.md`，告诉幻灯片生成模型*该页应涉及什么主题*。
   - **答案字段** — `key_numbers`、`key_terms`、`traps`、
     `key_figures`。这些仅流入 Stage 3 评分标准，是**评分密钥**。

   两者必须在内容层面保持不相交：任何出现在答案字段中的具体数值、
   命名比较、定理陈述、数据集规模、实验参数或正确表述，都**不得**
   在范围字段中重现。验收测试是结构性的：*仅读 `instructions.md`
   的人，能否写出幻灯片的定量结论、定理、参数值或正确措辞？*
   如果能，则范围字段吸收了答案内容，构成缺陷。
4. **忠实性优先于覆盖面。** 准确但范围较窄的表述优于含有捏造细节的
   更宽表述。
5. **具体数值锚点。** 正确性检查项中涉及数量的每个表述必须引用
   数值和条件（例如"压缩比 15:1 时指示热效率低于 46%"），而非
   仅用指标名称。
6. **Section 1 必须包含 `设计约束:` 行**，引用论文中真实的图/表
   标识符，至少在方法、结果和视觉分析相关幻灯片上。

## 输出纪律

- 要求返回 JSON 时，仅返回**一个** JSON 对象作为最终消息。前后
  无文字说明，无 markdown 代码块围栏。
- 要求写文件时，每个文件使用一次 Write 工具。
- 用 Read 工具阅读 PDF 一次；PDF 较大时使用 `pages` 参数。
- 本阶段的交付物写入磁盘、JSON 返回值准备好后立即停止。不要
  执行不必要的工具调用。
