# Stage 4b: 验证-精修评判评分标准

你的任务：验证并选择性改进现有的 `generation_task/judge_prompt.json`。
本阶段仅在 Stage 4 审计在关键质量轴上标出低分时运行。你执行五项
结构化任务——区分力评分、traps 覆盖交叉检查、定向内联修订、去重
和抽检——然后将修订后的评分标准原地写回。

**关键约束**：这是**定向修订**，不是全面重写。评分 3-5 的检查项
必须原样保留。研究表明，LLM 对评分标准的全面重写会导致 15-20% 的
F1 下降（语义漂移）。只有评分 1-2 的项可以删除、改写或拆分。

**反退化约束**：验证-精修步骤**绝不能**导致评分标准相对于输入
质量下降。具体而言：
1. **不要**合并已经原子化的项（评分 3-5）。将之前拆分的项重新
   合并为复合项是本阶段最常见的失败模式。
2. **不要**将 C1 或 C2 的检查项数量减少超过 20%。用户提示中
   指定了确切的最小数量——请遵守。
3. **不要**丢失覆盖点。输入评分标准覆盖的每个论文特定概念在
   输出中必须继续被覆盖。如果你删除了一个低分项，请确认其覆盖点
   被另一个项或你新增的项承接。
4. **不要**引入 `_paper_card.json` 中不存在的事实。之前的运行
   曾引入事实错误（如将参数值归因于错误的实验）。每个锚点值
   在写入前必须与 Paper Card 交叉核查。
5. 当你不确定是否应修改某个项时，**保留原样**。误保留（保留一个
   一般的项）远比误删除（丢失一个有效的覆盖点）损害小。

## 输入

- `_paper_card.json` — 结构化 Paper Card（所有锚点值的真实来源）。
- `_field_manifest.txt` — 自动生成的必覆盖清单。
- `generation_task/judge_prompt.json` — 待验证/精修的评分标准，
  包含两个数组：
  - `material_dependent_checklist_1` — 内容完整性（C1）。
  - `material_dependent_checklist_2` — 内容正确性（C2）。
- `_audit_report.json` — 触发本阶段的审计评分。

所有验证信号来自 `_paper_card.json`（外部数据），**不是**你自己
对论文的了解。**不要**编造 Paper Card 中不存在的事实。

## 检查项格式提醒

完整性项（C1）：
```
\n**<二元判断问题>？**\n\n  注意：您只需检查幻灯片是否包含所需内容，无需验证其正确性。\n  如果**否**，<描述缺失或不足之处>。\n
```

正确性项（C2）：
```
\n**<带具体锚点的二元判断问题>？**\n\n  如果**否**，<列出具体差异>。\n
```

## 任务 1 — 逐项区分力评分

对两个检查列表中的**每个**项进行 1-5 区分力评分。这决定了
哪些项是任务 3 的修订候选。

| 分数 | 标准 | 示例信号 |
|------|------|---------|
| 5 | 论文独有事实+具体锚点：具体数值+单位+条件，或对比"X 而非 Y"对 | "在 COCO 上达到 91.2% mAP，而非基线报告的 87.4%" |
| 4 | 论文特定术语+略泛化锚点——术语是本论文独有的，但锚点缺少具体值或对比对 | "正确描述了 NeRF 到网格的转换步骤" |
| 3 | 适度特定——引用了本子领域的概念，但缺少具体值或对比对 | "正确报告了模型的训练过程" |
| 2 | 半泛化——可以稍作改写就适用于类似论文，或捆绑了两个独立可测条件 | "实验结果是否准确呈现？" |
| 1 | 模板化——对任何论文都一样，无论文特定实体，或捆绑 ≥3 个独立条件 | "报告是否涵盖了方法论？" |

记录每个项的分数和一句话理由。

## 任务 2 — Traps 覆盖交叉检查

对 `_paper_card.json` 的 `traps` 数组中的每个条目（也在
`_field_manifest.txt` 中列为 TRAP1、TRAP2 等）：

1. 在所有 C2 项中搜索直接处理该 trap 的项。
2. 当 C2 项使用 trap 的 `correct_form` 作为正确答案**并**引用其
   `claim_to_avoid` 作为错误替代（或至少对比了正确方向）时，
   该 trap 才算"已覆盖"。
3. 列出每个未覆盖的 trap 及其 `kind`、`correct_form` 和
   `claim_to_avoid`。

## 任务 3 — 内联修订

基于任务 1 和 2，对检查列表进行定向编辑。

### 评分 1 的项（模板化）：
- **完全删除**。模板化项增加噪音，膨胀列表却不测试论文特定知识。
- 例外：3 项固定必需 C1 项（标题/结论/局限）无论评分如何都保留。

### 评分 1-2 的项（模糊或半泛化）：
- 用 `_paper_card.json` 中的具体锚点**改写**：
  - 使用 `key_numbers[*].claim` 的数值+单位+条件作为定量锚点。
  - 使用 `traps[*].correct_form` 和 `traps[*].claim_to_avoid`
    构建对比"X 而非 Y"对。
  - 使用 `key_terms[*].term` 和 `key_terms[*].common_confusion`
    构建定义项。

### 评分 1-2 的项（多条件捆绑）：
- **拆分**为单独的原子检查项，每个独立条件一项。
  每个拆分项必须独立构成一个二元是/否问题。

### 任务 2 中未覆盖的 traps：
- 为每个未覆盖的 trap **添加**新 C2 项，使用对比格式：
  "正确描述为 [correct_form]，而非 [claim_to_avoid]"。

### 修订约束：
- 评分 3-5 的项：**不动**。不改写、不重排、不"改进"已达标的项。
  **绝不**将两个评分 3+ 的项重新合并为一个复合项。
- **不要**重新合并测试不同概念的项。
- 新建和修改的项必须嵌入 `_paper_card.json` 字段中的具体数据——
  绝不编造数值。每个数字、单位和条件在写入前与 Paper Card 核对。
- 新建和修改的项必须遵循上述检查项格式。
- 输出 JSON 必须恰好有两个键：`material_dependent_checklist_1`
  和 `material_dependent_checklist_2`。
- 最终 C1 数量**不得**低于用户提示中指定的最小值。C2 同理。
- 问题部分：≤250 字符。"如果否"从句：≤150 字符。
- 总项：≤400 字符（嵌入 key_numbers 数据的项可达 500 字符）。
- 描述图/表**内容**，而非编号。

## 任务 4 — 去重检查

任务 3 的所有修订完成后，扫描所有项（C1 和 C2）的语义重叠：

- 标记 ≥70% 语义重叠的对：测试相同的 `_paper_card.json` 字段、
  使用相同锚点值、或用不同措辞问几乎相同的问题。
- 从每对重叠中删除不太具体的项。

## 任务 5 — 抽检（2-3 项）

抽样 2-3 个修改或新增的项。对每项：

1. **锚点准确性**：核实锚点值与 `_paper_card.json` 完全匹配——
   正确的数字、单位、条件、术语拼写。
2. **"如果否"具体性**：核实从句引导评判者指向具体缺陷，而非
   泛化的"描述问题"。
3. **标记发现的问题**，但此时不再进一步修改。

## 输出

编辑 `judge_prompt.json` 后，写入 `./_verify_refine_report.json`
并将同一 JSON 作为最终消息输出（无文字说明，无 markdown 围栏）。
报告必须通过 `_verify_refine_report.schema.json` 的校验。
