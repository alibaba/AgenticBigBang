# Stage 1: 文档画像（DocProfile）

本阶段的任务：仔细阅读 `material.pdf`，生成一个 JSON 对象——
*DocCard*——包含下游阶段写出高质量任务案例所需的所有信息。
本阶段不写其他文件。你生成的 DocCard 是后续阶段**唯一能看到的
数据源**。

## 本阶段可用的输入

- 工作目录中的 `material.pdf`。
- 工作目录中的 JSON Schema 文件 `_doc_card.schema.json`（由管线挂载）；
  你的最终 JSON 必须通过其校验。
- 工作目录末尾注入的**领域上下文**（Domain Context），包含文档类型
  提示和领域术语参考。

## 强制阅读流程

即使你认为可以跳过，也必须执行。

1. **Pass A — 封面与摘要/引言。** 阅读 `material.pdf` 第 1-2 页
   （封面 + 摘要/执行摘要/引言）。记录：精确标题、完整作者/主讲人
   列表、主要单位/机构、场合/会议名称（如有）、文档核心主旨。
2. **Pass B — 正文与图表。** 用一次大范围 Read 调用阅读完整正文。
   记录每个图/表的编号（使用文档原文形式：'图1'/'Fig. 1'/'Table 1'）、
   所在页码、展示内容。记录所有关键数据点、KPI、指标数值、
   政策条文数字等定量信息。
3. **Pass C — 术语与细节。** 再次扫描：
   - 专业术语/缩写词/命名的方法/模型/产品名
   - 流程/步骤的关键区分（例如"一期手术 vs 二期手术"、
     "标准版 vs 旗舰版"、"试点阶段 vs 推广阶段"）
   - 非单调趋势或最优点
   - 数据范围、适用条件、地域/时间边界
   - 局限性/风险/注意事项
4. **Pass D — 陷阱猎捕。** 对以下八类陷阱，判断文档是否存在风险，
   并用错误表述和正确表述同时记录：
   - `fabrication` — 幻灯片可能捏造文档中没有的数据、结论、功能。
   - `metric_misread` — 容易混淆的指标（例如"有效率"vs"治愈率"；
     "净利润"vs"营收"；"完成率"vs"增长率"）。
   - `non_monotone_flattened` — 文档中存在的非线性关系/先增后减，
     粗心的幻灯片可能简化为"越多越好"。
   - `condition_level_confusion` — 文档仔细区分的条件、阶段、版本
     或处理方式，粗心的幻灯片可能混淆。
   - `scope_overclaim` — 文档在特定条件/范围下得出的结论，
     幻灯片可能过度泛化。
   - `unit_or_definition_error` — 容易用错的单位或定义（%vs百分点、
     绝对值vs增量、年度vs季度数据等）。
   - `trend_direction_error` — "升高/下降/增加/减少"等趋势方向
     表述，粗心的幻灯片可能弄反。
   - `factor_misattribution` — 文档将某效果归因于特定因素，
     粗心的幻灯片可能归因错误。

## 填写 DocCard

Schema 是合同。写任何内容之前先阅读 `_doc_card.schema.json`。
几个关键澄清：

- `title`：完全忠实于封面/首页。
- `central_thesis`：一句话，捕获**核心主张 + 方法/途径 + 核心结论/价值**。
  避免"介绍了"、"分析了"、"阐述了"等模糊动词。使用中文。
- `source_event`：从封面、页眉页脚提取会议/场合名称和年份。
  如无，写"内部文档"或"N/A"。
- `document_type`：参考领域上下文中的文档类型描述选取最匹配的类型。
  例如：病例报告、技术方案、年度总结、政策宣讲、产品介绍、
  培训课件、行业分析、竣工汇报、活动策划等。
- `page_count_range`：根据文档页数确定幻灯片页数范围：
  - 1-4 页正文 → `[8, 12]`
  - 5-8 页正文 → `[10, 14]`
  - 9-12 页正文 → `[12, 16]`
  - 13+ 页正文 → `[14, 20]`
- `ordered_sections`：根据文档实际结构设计，**不要照搬学术论文模板**。
  根据文档类型，章节可以是：
  - 通用型：标题页 → 大纲 → 背景 → 核心内容章节 → 结论与建议
  - 报告型：标题页 → 执行摘要 → 主要成果/KPI → 详细分析 → 问题与建议
  - 培训型：标题页 → 大纲 → 背景与目标 → 核心知识模块 → 案例 → 要点总结
  - 方案型：标题页 → 背景与痛点 → 解决方案 → 实施计划 → 预期收益
  - 宣讲型：标题页 → 大纲 → 政策背景 → 主要内容条款 → 执行要求 → 问答

  标题页 bullets 格式固定：**从领域上下文的「标题页字段」获取准确字段名**，
  例如：
  - `文档标题: <标题>`
  - `作者: <作者>` 或 `主讲人: <主讲人>`
  - `单位: <单位>`
  - `场合: <会议/场合>` 或 `会议: <会议>`

- `key_numbers`：所有定量锚点（数值、比例、金额、日期跨度、
  数量等），每条必须包含数值+单位+条件。最少 3 条，尽量提取所有
  有区分度的数值。
- `key_figures`：文档中所有重要图/表，至少 1 个。
- `key_terms`：文档特定的专业术语，至少 3 个。
- `traps`：最少 3 个，优先捕获数值方向错误、指标混淆和归因错误。

## 关于答案字段 vs 范围字段

`key_numbers`、`key_terms`、`traps` 是**答案字段**——它们将成为
评分密钥，不得流入 `instructions.md`。`ordered_sections.bullets` 是
**范围字段**——只描述幻灯片的主题和视角，不包含具体数值答案。

测试：*仅读 `instructions.md` 的人，能否写出幻灯片的定量结论？*
如果能，则 bullets 吸收了答案内容，构成缺陷。
